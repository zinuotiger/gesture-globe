# Gesture Engine progress and contracts

TASK-405 exposes the pure `GestureEngine.update(VisionFrame) -> GestureIntent[]`, reset and bounded debug state. It composes primary-hand selection, feature extraction, temporal filtering and the Open Palm rule. Open Palm needs four stable entry frames, uses the lower hold threshold after entry, releases after three low-hold frames and ends immediately on no valid hand. START establishes the action anchor and has zero delta. UPDATE converts smoothed displacement through actual dt, speed deadzone/cap, configured gains and inversion. When raw hand motion stops, its axis outputs zero rather than following an EMA settling tail.

Frames with invalid/nonfinite data, wrong established session, stale age or duplicate/order violations cannot drive movement. Session changes require an explicit reset (App will do this during lifecycle integration). Large gaps, hand switches and outliers cancel the old action; they do not bridge motion across missing data. Reset returns cancellation intents for the caller to route through Interaction before disposing the session. The engine never manipulates camera, DOM or Globe directly.

TASK-406 adds Closed Fist as a clutch. Its candidate suppresses lower-priority rotate updates immediately; after two stable frames, active ROTATE:CANCEL precedes PAUSE:START in the same returned list. While held or releasing, no movement updates are produced and motion anchors are cleared. Three low-score frames release with PAUSE:END; loss ends immediately. The first new rotation still needs fresh stability and zero-delta START, even after substantial repositioning. Reset, stale or invalid input explicitly cancels a paused gesture. Holding fist is not a toggle.

TASK-407 adds geometric Pinch: valid palm width and control geometry, filtered ratio <=0.30 for entry, ratio <0.40 for hold, three stable entry frames and three exit frames. ZOOM:START has zero delta; later delta.y is a bounded log-distance increment from smoothed palm Y and actual dt, with configurable inversion. Finger separation changes alone never set zoom amount. No absolute anchor offset is accumulated, so downstream distance limits cannot create hidden displacement. The gesture's confidence reports selected-hand quality, not a calibrated probability of pinch. Pinch cancels lower-priority rotation before starting; Fist cancels zoom before pause. EMA may delay a near-threshold ratio crossing; fixed tests distinguish filtering from hysteresis/release counts.

TASK-408 adds Victory: six frames at score >=0.78 yield RESET:TRIGGER with no movement payload. Holding cannot retrigger even after 1200ms; physical departure and cooldown are both required. A caller-supplied manualInputLocked flag blocks candidates without faking departure or rearming. Fist takes precedence; Victory suppresses lower-priority movement. Cooldown belongs only to Victory so other gestures remain available. Invalid frames cancel candidates but preserve the armed/cooldown budget. Explicit session reset clears that budget. No reset command is executed directly here; Interaction will arbitrate the returned intent.

TASK-409 adds Pointing at score >=0.72. SELECT:START/UPDATE carry only the normalized, unmirrored EMA landmark-8 pointer; they do not select a place, generate selectionId, or trigger after elapsed time. M06/M07 will adapt mirror/safe-area coordinates, check UI occlusion and actual globe hits, and own dwell. Missing/low-confidence hands immediately END the pointer stream; higher-priority candidates, reset, stale input or broken anchors CANCEL it without a tail pointer. Pointing preempts Open Palm. START has no movement delta; no fabricated hit state exists in Gesture Engine.

All five gesture modes are implemented at this checkpoint. TASK-410 centralizes every emitted intent through the pure IntentMapper and exact public schema; see gesture-intent-contract.md for phase/payload rules. No production classifier is replaced by synthetic test poses. First-party synthetic fixtures prove mathematical transitions and approximate steady-rate invariance, not real-human direction preference, recognition quality or latency. Actual App wiring remains TASK-508, human tuning/acceptance remains deferred.
